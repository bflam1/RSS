Mend AppSec Platform: Version 26.7.1 (26-July-2026)

2026-07-26T00:00:00+00:00

New Features and Updates

  • Mend Platform now includes a centralized Activity Log, giving administrators visibility into user and system activity.

    • Complete event trail - platform activities, configuration changes, and security & legal findings actions across all engines (Platform, Dependencies, Code, Containers, AI), with 18 months of retention.

    • Audit-grade detail - every event captures the actor, timestamp, and scope; audit events include full Before/After change records.

    • Filter, sort, investigate - slice by date, event, category, event type, engine, user, application, or project, and drill into any event via the details side panel.

    • Reporting & automation - generate an Excel Activity Log report from the Reports area or directly from the Activity Log page, or retrieve events programmatically via API.

    • Account-level coverage — account-scoped actions (custom roles, global workflows, account-level reports, SAML integrations) are logged across all organizations within the account and visible only to Account Admins.

  • Enhanced the SCA tool in the Agentic Integrations to display vulnerabilities from transitive dependencies, helping developers make more informed decisions during project analysis.

Resolved Issues

  • Fixed an issue where long running scans caused projects metrics to be zeroed out in the Mend Platform.

  • Fixed an issue where Jira tickets were intermittently not created during SCA scans due to unauthorized request errors and incorrect issue type mappings. The integration now correctly validates project and issue type associations to ensure reliable ticket generation.

Mend SAST: Version 26.7.1 (27-July-2026)

2026-07-27T00:00:00+00:00

New Features and Updates

  • The Project Risk Factors section in the Mend Platform now includes an evidence page. When you click on a risk factor classification — such as Payments, Healthcare, or PII — you can see the specific code signals that led to that classification, including function names, class names, imports, and file paths. This makes it easier to understand and verify why a project was classified the way it was, giving you full transparency into the AI-based risk assessment.

  • Mend SAST now supports Python for CWE-614 (Sensitive Cookie Without 'Secure' Attribute).

  • Mend SAST now includes detection for CWE-642 (External Control of Critical State Data) in Java.

  • Mend SAST now includes detection for CWE-284 (Improper Access Control / Unsafe Permission Check) in Java.

  • Improved the detection accuracy in Java and JavaScript (Gen2) engines across several CWE categories, including SQL Injection (CWE-89), Path Traversal (CWE-22), and Cross-Site Scripting (CWE-79).

  • Updated the Mend SAST detection engine for Scala to include support for CWE-94: Improper Control of Generation of Code ('Code Injection').

  • Improved the accuracy of Scala security scans by refining the sanitization logic for Server-Side Request Forgery (SSRF) detection.

  • Mend SAST now supports CWE-319 (Cleartext Transmission of Sensitive Information) for the Go programming language.

Resolved Issues

  • Fixed an issue where Mend SAST incorrectly flagged FIPS-approved cryptographic algorithms, such as Elliptic Curve (EC) and PBKDF2WithHmacSHA256, as insecure under CWE-327.

  • Fixed an issue where false-positive XSS vulnerabilities were incorrectly flagged in Python environments.

  • Fixed an issue where the secrets detection engine incorrectly flagged Mend SAST cache files as false positives when the cache directory was located within the scanned target directory. The engine now automatically excludes Mend's internal cache, binary, and log directories from secrets detection.

Mend Developer Platform: Version 26.7.1 (26-July-2026)

2026-07-26T00:00:00+00:00

New Features and Updates

  • Mend Developer Platform for GitLab.com, which has been in closed beta for several weeks. is now generally available.
    Mend Developer Platform for GitLab Cloud integrates seamlessly into your native GitLab environment, scanning your repositories as part of your Mend account. Built directly into GitLab Cloud, it detects all open-source components and custom code, and provides clear, consolidated visibility into all findings.

  • The scan token is now visible within the job details block on the job page, located directly beneath the scan status row. This update includes a convenient copy button for the scan token, simplifying the debugging process by providing quick access to essential job information.

  • Improved the webhook processing efficiency by transitioning the controller's autoscaling logic from queue depth to oldest-message age. This update ensures that scaling is triggered based on actual wait times, aligning more closely with service level objectives. Additionally, new metrics and structured logging have been implemented to provide better visibility into the full webhook lifecycle, including queue wait times and processing durations, allowing for more proactive capacity management and improved overall system throughput.

Resolved Issues

  • (AZDO) Fixed an issue where Azure DevOps custom work item states, such as "In Progress" or "Resolved," were ignored and reset to "New" during scans. The integration now correctly respects these states, ensuring that manual updates to work item status are preserved and not overwritten.

Mend for GitHub Enterprise: Version 26.7.1.2 (27-July-2026)

2026-07-27T00:00:00+00:00

Unified Agent 26.6.2 | Renovate 43.272.4 | Remediate 26.7.1 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • (SAST) GitHub issues created for SAST findings now include the full data flow trace, showing each step of how tainted data moves through the code. The check run summary has been simplified to a brief overview with a direct link to the corresponding issue, so developers get the right level of detail in the right place without leaving GitHub.

  • (SAST) Users can now trigger /mend code actions by replying directly to Mend's finding comment in PR conversations, instead of posting a separate comment at the bottom of the PR.

Resolved Issues

  • Fixed an issue where transient failures during the retrieval of inherited configuration files caused scans to silently fall back to default settings. This resulted in inconsistent scan results being cached and applied to subsequent processes. The system now correctly identifies these retrieval errors, ensuring that configuration is not downgraded to defaults and that failed attempts are not cached, providing more reliable and consistent scan outcomes.

  • Fixed an issue where scan results were not displayed on pull request check runs due to the summary exceeding the maximum byte size limit. The truncation logic now correctly measures UTF-8 byte length instead of character count, ensuring that summaries containing multi-byte characters or icons are properly processed and accepted by GitHub.

  • Fixed an issue where the "Retrieve pending webhooks" API incorrectly returned zero for pending and running counts, even when webhooks were queued. The response mapping has been corrected to accurately reflect the actual number of pending and in-progress webhooks. Note that the running count represents a snapshot and serves as an approximation of currently processed webhooks.

  • Upgraded the Java runtime to Eclipse Temurin 17.0.19 to enhance security and performance.

  • (SCA) Fixed an issue where the Poetry engine failed to resolve dependencies for projects using the legacy dev-dependencies section on Poetry 2.x environments. The engine now correctly identifies the Poetry version and applies the appropriate exclusion flags, ensuring accurate dependency detection and preventing false-negative scan results.

  • (SCA) Fixed an issue where the scanner would enter an infinite loop when parsing Maven POM files containing circular property references. The parser now identifies and skips properties that reference themselves, preventing scan failures and ensuring the process continues smoothly.

  • (SCA) Fixed an issue where Gradle scans injected Maven Central ahead of a project's private repository. This caused dependency resolution to prioritize public repositories, leading to excessive network requests and build failures in environments restricted to private registries. The resolution order has been corrected to ensure private repositories are prioritized, preventing unnecessary external calls.

  • (SCA) Fixed an issue where Gradle scans failed with out-of-memory errors when an unresolvable Java home was specified in the `gradle.properties` file. The scan process now correctly preserves critical memory configurations and JVM arguments when falling back to the system's Java installation, ensuring successful dependency resolution for large projects.

  • (SCA) Fixed an issue where Gradle dependencies could not be resolved in React Native pnpm workspace projects. This occurred because the Gradle build failed to locate the `@react-native/gradle-plugin` in the root directory after a pnpm installation, preventing successful dependency resolution. The fix ensures that the plugin is correctly referenced, allowing Gradle builds to complete successfully in monorepo environments which rely on the SCA Orchestrator.

  • (SCA) Fixed an issue where the SCA check run's "Issue" column incorrectly displayed "None" for scoped npm packages. This occurred because a title sanitization process prevented proper matching between GitHub issues and their corresponding dependencies, leading to duplicate issue creation. The fix ensures that issue titles for scoped packages are correctly preserved, restoring accurate linking and preventing redundant notifications.

  • (SCA) Fixed an issue where the Unified Agent would execute a full pip resolution on stub setup.py files lacking name and version metadata. This resulted in false-positive "Failed to get hierarchy tree" errors. The resolver now correctly handles these metadata-less files to ensure accurate dependency analysis.

  • (SCA) Fixed an issue where the SCA Reachability S3 cache client failed to authenticate using IAM instance roles when static access keys were not provided. The S3 client now supports a credential provider chain for IAM roles and environment variables. Additionally, client validation was updated to require only bucket-scoped permissions, ensuring compatibility with least-privilege security policies and preventing silent cache failures.
