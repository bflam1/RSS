Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.6.1 (28-June-2026)

2026-06-28T00:00:00+00:00

New Features and Updates

  • Introducing a new scan comparison feature that allows users to compare two scans from the same engine to visualize added, removed, or modified findings. This engine-agnostic tool supports SCA, SAST, Containers and AI, providing a unified view of security, legal, and library changes. Users can initiate comparisons via an intuitive UI or public API.

  • The Risk Factors column on the Applications and Projects views has been consolidated into a single, unified view. This update replaces separate engine-specific columns for Dependencies, Code, and AI with a centralized display that now also includes Container risk factors. Users can view aggregated risk icons across all four engines in one cell, access a detailed breakdown via an enhanced tooltip, and utilize engine-sectioned filters for more efficient risk management and navigation.

  • Updated the Containers Findings Search tab to align with the Dependencies findings search design, providing a consistent and streamlined user interface across the platform.

  • The MCP server can now fetch optimized rules for any supported AI coding assistant (such as Cursor, Claude Code, VS Code Copilot, and Windsurf). To trigger it, prompt your agent with "Download the newest rules for Mend MCP". You can also periodically trigger it to check if the rules have been updated.

Resolved Issues

  • (Container) Fixed an issue where project exclusions defined in workflow scope conditions were not being honored during container image scans. This resulted in policy violations being incorrectly generated for projects that should have been excluded from evaluation. The fix ensures that excluded projects are correctly identified and bypassed, preventing unnecessary violations and streamlining scan results.

  • (SCA) Fixed an issue where corrected license metadata for npm and PyPI artifacts failed to sync and render accurately in the inventory. This fix ensures that license relationships consistently reflect updated metadata, allowing manually added licenses to be correctly identified and managed within the Mend Platform UI.

Mend SCA: Version 26.6.1 (28-June-2026)

2026-06-28T00:00:00+00:00

New Features and Updates

  • The Mend Platform now displays the original source of CVSS scores, such as NVD or MITRE, within the UI and APIs. This update provides greater transparency into how vulnerability scores are determined and helps clarify discrepancies between different scoring providers.

  • The following reports are now available at the organization level in the UI, and can also be generated via API at the application/project level:

    • Dependencies Attribution

    • Dependencies Due Diligence

    • Dependencies Inventory

  • Introduced a new "Unspecified Copyrights" state to the OS Inventory, providing greater clarity and control over legal data. Users can now filter the inventory by this specific state and view a dedicated visual indication in the table, ensuring that components with unspecified copyright information are easily identifiable and no longer grouped with those that have confirmed copyrights.

  • The OS Inventory page now includes a "Number of Licenses" column, providing a quick overview of the total licenses detected for each library. This enhancement allows users to easily assess licensing complexity directly from the inventory table without needing to view individual component details.

Resolved Issues

  • Fixed an issue where some Conda-Forge packages were not correctly imported into the Mend Inventory.

  • Fixed an issue where corrected license metadata for npm and PyPI artifacts failed to sync and render accurately in the inventory. This fix ensures that license relationships consistently reflect updated metadata, allowing manually added licenses to be correctly identified and managed within the Mend Platform UI.

Mend SAST: Version 26.6.1 (29-June-2026)

2026-06-29T00:00:00+00:00

New Features and Updates

  • Increased the detection accuracy for Python, especially for the following CWEs:

    • CWE-22: Path Traversal

    • CWE-78: Command Injection

    • CWE-79: Cross-site Scripting

    • CWE-117: Log Forging

  • Enhanced JavaScript analysis by adding the local storage as a low-probability source. This update improves the detection of potential client-side vulnerabilities, such as stored DOM XSS, by identifying data retrieved from local storage as a possible point of origin for tainted input.

  • Increased the detection accuracy for Java, especially for CWE-117: Log Forging.

Resolved Issues

  • Fixed an issue where the "fromDate" and "toDate" fields were incorrectly included in standard JSON reports with zeroed values. These fields, intended only for resolved findings reports, have been removed from standard reports to ensure data clarity and accuracy.

  • Fixed an issue where code snippets were missing from SAST reports if a previous scan in the same project had the snippet size set to zero. Subsequent scans with code upload enabled now correctly include the expected code snippets in the generated reports.

  • Fixed an issue where "Weak Hash Strength" findings were incorrectly grouped by vulnerability name alone, leading to inconsistent CWE mapping in reports. The grouping logic now utilizes both the vulnerability name and the specific CWE ID (such as CWE-328 or CWE-916) to ensure accurate reporting across different programming languages.

  • Fixed an issue where multiline suppression justification comments submitted from GitHub were truncated to the first line in the Mend Platform. The full multi-line text is now correctly preserved and displayed.

  • Fixed an issue where a single line of code snippet remained visible in the Mend Platform UI and reports even when the snippet size was set to zero in the latest scan.

  • Fixed an issue where the VB.NET engine failed to scan files when the Windows system locale was set to Traditional Chinese (cp950).

Mend AI: Version 25.12.1 (05-January-2026)

2026-01-05T00:00:00+00:00

New Features and Updates

  • (Premium / Core) Introducing System Prompt Risk (open beta), a new detection and remediation offering by Mend AI, for mitigating risks posed by system prompts used in conversational AI interfaces.

    • A new System Prompt Risk table inventories system prompts and provides quick export/sharing and deep-link side panel for prompt context.

    • System Prompt Risks are integrated into the existing AI Security Risk Factors across Projects and Applications. The classification appears as a Conversational Interface chip, is filterable, and automatically participates in dashboards and workflows.

    • Remediation in the form of a hardened system prompt is available in the System Prompt side panel, providing clear, copy-ready remediation guidance for AppSec engineers and developers.

    • The AI Security Dashboard has been enriched with system prompt risk data.

    • System prompt risk data is also available via API.

Mend CLI: Version 26.6.1 (29-June-2026)

2026-06-29T00:00:00+00:00

Resolved Issues

  • (SCA) Fixed an issue where Mend CLI failed to detect dependencies in Python projects using the PEP 621 standard in `pyproject.toml` files. This occurred because the scanner incorrectly identified these files as Poetry-related, leading to zero reported dependencies. The detection logic has been updated to correctly identify and scan PEP 621-compliant projects, ensuring all direct dependencies and associated vulnerabilities are accurately surfaced.

  • (SCA) Fixed an issue where Poetry scans failed when the system Python version was outside the project's required range. Although Mend SCA correctly installed a compatible Python version, the Poetry CLI continued to execute using the original system interpreter, leading to dependency resolution errors. The scan process has been updated to ensure the Poetry CLI uses the newly installed, compatible Python environment, allowing for successful dependency resolution and accurate scanning of Poetry-managed projects.

  • (SCA) Fixed an issue where the npm resolver produced duplicate dependency entries when the same package was reachable through multiple ancestor chains. The resolution logic now correctly deduplicates packages based on name and version, ensuring each unique dependency appears only once in the dependency tree for more accurate scan results.

This resulted in false-positive "Failed to get hierarchy tree" errors. The resolver now correctly handles these metadata-less files to ensure accurate dependency analysis.

Mend Developer Platform: Version 26.6.1 (28-June-2026)

New Features and Updates

  • (GitHub) Enhanced the onboarding process to support organizations with up to 10,000 GitHub repositories, ensuring a smoother experience for large-scale enterprise customers using the developer platform.

Resolved Issues

  • (AZDO) Fixed an issue where Azure DevOps tasks failed to complete following an SCA scan. This occurred due to a race condition where a pull request created immediately after a commit push caused the scan to lose its pull request ID during deduplication, leaving the status check in a pending state. The logic has been updated to ensure the pull request ID is correctly preserved and the status check is finalized.

Mend for GitHub Enterprise: Version 26.6.1.2 (28-June-2026)

2026-06-28T00:00:00+00:00

Unified Agent 26.5.1 | Renovate 43.235.0 | Remediate 26.6.1 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • Introduced a new configuration field, `arrayInheritanceSetting`, which allows users to control whether specific array-type fields in the local `.whitesource` file append to or override global values from `repo-config.json`. This update enables more granular control over repository settings, such as the ability to re-enable scan customization hooks for individual repositories even when they are disabled globally. Supported fields include scan settings, base and release branches, and issue settings.

  • (SCA) Java 25 projects are now supported in SCA scans.

  • (SAST) It's now possible to control which GitHub repositories are included in or excluded from SAST scanning directly from global-config.json, using the new sast sub-key unde ignoredRepos and includedRepos. This allows a gradual SAST rollout across an organization without modifying per-repository .whitesource files and without affecting other scanners. Applies to GitHub repositories configured via .whitesource.

  • (Renovate Enterprise Self-hosted) Introduced a comprehensive Dependency Dashboard in the Renovate Self-hosted Web UI, providing users with centralized visibility and actionable control over dependency management. The dashboard features dedicated sections for repository notes and warnings, detected dependencies, and suggested updates. Users can now directly trigger Renovate jobs, create or open pull requests, and retry or rebase updates. This enhancement streamlines workflows and ensures parity for environments where in-repository dashboards are unavailable.

  • (Renovate) (Open Beta) Mend Remediate can be replaced with Renovate EE with all its features, APIs, Web-UI and all additional features to come. This allows existing Mend Repository Integration users to deploy Renovate EE instead of the existing Remediate containers.

    More documentation on this can be found at Remediate docs.

Resolved Issues

  • Fixed an issue where GitHub issues were incorrectly closed when the project hierarchy response exceeded the 200MB size limit. The system now correctly identifies these large responses as API failures rather than empty projects, ensuring that existing GitHub issues remain open and untouched when a scan cannot be completed due to response size constraints.

  • Fixed an issue where renaming a repository and triggering a scan from a non-default branch caused the default branch project to be incorrectly named with a literal "_DEFAULT_BRANCH" suffix. This fix ensures that project names are correctly synchronized with the new repository name across all branches, maintaining consistent naming conventions.

  • (SCA) Fixed an issue where Mend SCA check runs were not created for pull requests originating from forks within the same GitHub organization. The system now correctly identifies same-organization forks by comparing the full repository name, ensuring that security scans are triggered for all fork-based pull requests.

  • (SCA) Fixed an issue where the `gradle.additionalArguments` parameter was not correctly applied when defined within the `whitesource.config` file during repository integrations.

  • (SAST) Fixed an issue where manual SAST scans could be triggered via the API even if SAST was not enabled for the target repository. The system now correctly verifies repository settings before initiating a scan, ensuring that no check-runs or security reports are generated for repositories without SAST enablement.

  • (Remediate) Fixed an issue where Mend Remediate incorrectly opened First Fix pull requests instead of Least Vulnerable Package (LVP) pull requests, even when the LVP feature was enabled in the repository integration. The fix ensures that the preferred LVP version is correctly identified and proposed to minimize security risks.

  • Several CVE fixes.

  • Fixed an issue where renaming a repository in GitHub Enterprise (GHE) multi-org deployments failed to update the corresponding Mend project name, even when `repoNameSync` was enabled. This occurred due to an authentication error when the system incorrectly used administrative credentials instead of the specific user's email for the update process. The synchronization now correctly updates both project names and tags across all GHE deployment types.
