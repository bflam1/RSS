Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.7.2 (09-August-2026)

2026-08-09T00:00:00+00:00

New Features and Updates

  • Mend DAST now supports the new Invicti Platform, enabling seamless ingestion of assets, vulnerabilities, and scans via its latest API. This update introduces a dedicated integration card for the Invicti Platform while maintaining the existing integration, now renamed Invicti Enterprise. Users benefit from enhanced data mapping, including structured vulnerability classifications and CVSS v4 scoring, ensuring comprehensive security coverage across both legacy and modern Invicti environments.

Resolved Issues

  • Fixed an issue where the Libraries tab under Security > Dependencies failed to load for certain applications, resulting in indefinite loading states or 403 errors. The system now correctly retrieves and displays the application's library list as expected.

  • Fixed an issue where filtering the OS Inventory table by project caused an infinite loading spinner. The system now correctly handles project search parameters, ensuring the table updates accurately and displays the relevant results without requiring a page refresh.

  • (SCA) Fixed an issue where the reachability count for libraries was reported inconsistently across different views. The reachable count now displays correctly in the Summary view, ensuring alignment with the Security Dependencies data.

Mend SCA: Version 26.7.2 (09-August-2026)

2026-08-09T00:00:00+00:00

Resolved Issues

  • Fixed an issue where direct libraries with security findings were missing from the Direct Libraries tab in source-matched C/C++ projects. This occurred even when libraries were correctly identified as direct dependencies, preventing them from appearing in filtered results. The Direct Libraries tab now accurately displays all direct libraries with findings on themselves or within their dependency tree, ensuring consistent visibility across all project types.

  • Fixed an issue where the reachability count for libraries was reported inconsistently across different views. The reachable count now displays correctly in the Summary view, ensuring alignment with the Security Dependencies data.

Mend SAST: Version 26.7.2 (10-August-2026)

2026-08-10T00:00:00+00:00

New Features and Updates

  • Introducing the Gen 2 Ruby detection engine, with improved CWE and framework coverage for accurate, scalable scans.

  • The Scala detection engine is now generally available, delivering increased coverage and accuracy for Scala code analysis.

  • The compliance standards section in the Mend Platform now shows, for each standard, how many findings violate it. That count is clickable, and selecting it takes you directly to the list of findings that violate that specific standard, so you can move from a compliance overview straight to the exact findings you need to review.

Resolved Issues

  • Fixed an issue where Mend SAST incorrectly flagged `getIntent()` calls in non-exported Android Activities as potential vulnerabilities.

  • Fixed an issue where Mend SAST incorrectly flagged log messages in Android Java applications when the message consisted solely of fixed string literals or compile-time constants.

  • Fixed an issue where the iOS Objective-C engine incorrectly identified `NSMutableDictionary` as a vulnerability, resulting in false-positive Insecure Data Storage findings.

  • Fixed an issue where the iOS Objective-C engine could experience memory inefficiency and stalls when processing dense C preprocessor macro blocks.

  • Fixed an issue where the JavaScript engine incorrectly flagged false-positive Open Redirect (CWE-601) findings when processing server-rendered attributes.

  • Fixed an issue where JavaScript / TypeScript detection engine reported false-positive findings for DOM-based XSS.

Mend Container: Version 26.7.2 (09-August-2026)

2026-08-09T00:00:00+00:00

New Features and Updates

  • Mend Container now supports SBOM import, allowing you to ingest container inventory and risk data from CycloneDX and SPDX files to create a new project. This new capability, available via the Platform UI and platform API, enables teams to manage security for air-gapped builds or third-party images by identifying OS-level packages and language ecosystems. Imported projects are automatically matched against the Mend vulnerability database to ensure accurate risk assessment without requiring a live image scan.

Resolved Issues

  • Fixed an issue where large image scans would occasionally fail to complete within a reasonable timeframe. This update optimizes the scanning process for high-capacity images, ensuring consistent performance and reliable completion of security assessments.

Mend AI: Version 25.12.1 (05-January-2026)

2026-01-05T00:00:00+00:00

New Features and Updates

  • (Premium / Core) Introducing System Prompt Risk (open beta), a new detection and remediation offering by Mend AI, for mitigating risks posed by system prompts used in conversational AI interfaces.

    • A new System Prompt Risk table inventories system prompts and provides quick export/sharing and deep-link side panel for prompt context.

    • System Prompt Risks are integrated into the existing AI Security Risk Factors across Projects and Applications. The classification appears as a Conversational Interface chip, is filterable, and automatically participates in dashboards and workflows.

    • Remediation in the form of a hardened system prompt is available in the System Prompt side panel, providing clear, copy-ready remediation guidance for AppSec engineers and developers.

    • The AI Security Dashboard has been enriched with system prompt risk data.

    • System prompt risk data is also available via API.

Mend Developer Platform: Version 26.7.2 (09-August-2026)

2026-08-09T00:00:00+00:00

New Features and Updates

  • The Mend Developer Platform now includes dedicated sections for Deprecations and Abandoned packages in the frontend. This update provides users with clearer visibility into the status of their dependencies, allowing for better-informed decisions regarding package maintenance and security.

  • Improved the user experience in the Mend Developer Platform by refining the job status logic. The job status column now remains in a "Running" or "Processing" state until scan results are fully published. This ensures that a "Done" status is displayed only when the scan conclusion and findings are available, providing a more accurate representation of scan progress across all engines and SCMs.

  • To improve the onboarding experience, a "first sync in progress" status for organization cards was introduced on the homepage. When the onboarding flow is completed, any organization still undergoing its initial backend synchronization will now appear as a visible, pending card with clear status indicators. This ensures a user can immediately verify that an organization was added successfully, even while the background setup process is finishing.

  • (SAST) SAST scans on the Developer Platform now start faster due to improved caching mechanism.

  • (Renovate) Introduced the ability to view worker logs directly within the Renovate CE/EE web interface. Users can now access comprehensive job details, including worker-level logs that are prepended and appended to the standard Renovate logs, providing deeper visibility into job execution and errors.

Resolved Issues

  • (AZDO) Fixed an issue where Azure DevOps projects with incomplete onboarding appeared as active cards on the Developer Platform home page, leading to a 404 error when clicked. These projects now correctly display an "Onboarding incomplete" status, providing clear visibility into their state and guiding users to complete the installation process.

  • (GitLab.com) Fixed an issue where the repository dropdowns remained empty during the custom selection step of the GitLab.com onboarding process. The dropdowns now correctly list all available repositories within each selected group, ensuring a seamless and accurate selection of specific projects.

  • (SCA) (AZDO) Fixed an issue where a change in a package-lock.json file wouldn't trigger a dependencies scan. This fix ensures that any changes to dependencies within the lock file correctly trigger a scan, providing more comprehensive coverage for repository updates.

Mend for GitHub.com: Version 26.7.2 (09-August-2026)

2026-08-09T00:00:00+00:00

New Features and Updates

  • Enhanced diagnostic logging for the webhook consumer to provide better visibility into queue-claim attempts and idle periods. This update allows for more effective troubleshooting of webhook processing delays by capturing detailed logs of claim outcomes and sleep durations when the queue is empty. These logs are disabled by default and can be activated via environment variables for targeted investigations, ensuring no impact on standard system performance while improving overall observability.

  • (SAST) Remediations are now triggered by commenting /mend remediate, instead of by a checkbox. Mend replies with a confirmation comment once the command is processed, including a clear message if something goes wrong. Existing pull requests and issues continue to work as before.

Resolved Issues

  • Updated the reachability scan flow to ensure the `isBaseBranch` parameter is correctly passed during scan requests. This alignment across all scan paths ensures consistent scan parameter handling for repository integrations, improving the accuracy of branch-specific scan data.
