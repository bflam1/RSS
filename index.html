Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.9.1 (27-September-2026)

2026-09-27T00:00:00+00:00

Resolved Issues

  • Fixed an issue where the user key generation error notification displayed a generic message instead of the specific reason provided by the backend. The notification now surfaces the actual cause, such as reaching the maximum number of user keys, to provide clearer guidance for resolution.

  • Fixed an issue where the Malicious findings banner on the Security dashboard incorrectly included removed libraries in its total count. The banner now accurately reflects only active malicious software components, ensuring consistency with the legacy interface.

  • (SCA) Fixed an issue where users with application-level roles, such as Application Admin or Security Analyst, received an "Access is denied" error when attempting to create a Jira issue from an SCA finding. The system now correctly evaluates permissions at the application scope, allowing authorized users to generate Jira tickets without requiring organization administrator privileges.

  • (SAST) Fixed an issue where Mend CLI SAST scans failed to return exit code 9 and did not break the pipeline, even when workflow violations were detected and the "Fail Pipeline on Violation" setting was enabled. The CLI now correctly enforces workflow policies by returning the appropriate exit code to ensure pipeline failures occur as expected when security violations are identified.

  • (Container) Fixed an issue where updating a registry integration could overwrite stored service-user credentials with invalid data, causing subsequent scheduled scans to fail. The fix ensures that service-user state is managed server-side and includes a recovery mechanism to automatically refresh credentials if authentication failures occur during a scan.

  • (Container) Fixed an issue where the Containers view displayed outdated scan data because the latest scan pointer failed to advance upon scan completion. The logic has been corrected to ensure the Containers view consistently reflects the most recently finished scan.

Mend SCA: Version 26.9.1 (27-September-2026)

2026-09-27T00:00:00+00:00

New Features and Updates

  • (Open Beta) The Mend CLI and the Mend Repository Integrations now support the Bun package manager for JavaScript projects. This update allows for the automatic detection and reporting of both direct and transitive dependencies in projects using `package.json` alongside `bun.lock` or `bun.lockb` files, ensuring secure and reliable dependency management for the Bun ecosystem.

Resolved Issues

  • Fixed an issue where users with application-level roles, such as Application Admin or Security Analyst, received an "Access is denied" error when attempting to create a Jira issue from an SCA finding. The system now correctly evaluates permissions at the application scope, allowing authorized users to generate Jira tickets without requiring organization administrator privileges.

  • Fixed an issue where the Malicious findings banner on the Security dashboard incorrectly included removed libraries in its total count. The banner now accurately reflects only active malicious software components, ensuring consistency with the legacy interface.

  • Fixed an issue where the reachability engine retained dependency graphs and traces in memory longer than necessary, leading to excessive heap usage and potential out-of-memory errors during large scans. The analysis process now merges dependency graphs incrementally and releases them immediately, caps vulnerability traces at insertion, and clears collector state between modules. These optimizations significantly reduce the memory footprint, ensuring more stable performance and successful completion of scans within standard container memory limits.

  • Fixed an issue where Java reachability analysis incorrectly reported vulnerabilities as unreachable in multi-module Maven repositories. This occurred when dependencies were declared in modules without Java source files, such as aggregator or test-harness modules, causing the analysis to skip them. The analysis now evaluates dependencies against the repository-wide source set, ensuring accurate reachability verdicts across all modules.

  • Fixed an issue where Java reachability analysis on large multi-module repositories could time out after 30 minutes, causing scans to silently drop results while reporting success. The analysis now utilizes a more efficient forward-traversal approach, significantly reducing processing time. Additionally, timeouts are now handled per module to ensure that a failure in one module does not prevent the analysis of others, and any such occurrences are clearly reported in the scan metrics.

  • Fixed an issue where large or complex Gradle dependency graphs caused a stack overflow error during Java reachability analysis. This resulted in scans silently failing while incorrectly reporting a successful status. The analysis engine now handles deep dependency structures and cyclic references more efficiently, ensuring accurate reachability results and proper error reporting for large-scale projects.

Mend SAST: Version 26.9.1 (28-September-2026)

2026-09-28T00:00:00+00:00

New Features and Updates

  • The Mend CLI SAST scan (mend code) now supports a --print-to-console flag that prints the CLI logs directly to the console (stdout) as the scan runs, in addition to writing them to the log file.

  • Improved the AI-generated remediation suggestions for CWE-117 (Log Forging) in Python code. The remediation now correctly neutralizes carriage return (CR) and line feed (LF) characters instead of applying HTML escaping. Additionally, the suggestion ensures all client-controlled values within the log statement are sanitized, providing a more comprehensive and effective fix for log forging vulnerabilities.

  • Default exclusions in mend code CLI scans now ignore /_MACOSX/..* metadata files across all SAST scan engines. This update prevents macOS-specific system files from interfering with the TreeSitter parser during scans on Windows environments, ensuring more stable and accurate analysis. These exclusions are applied automatically via centralized settings, even when default exclusions are otherwise disabled.

Resolved Issues

  • Fixed an issue where Mend CLI SAST scans failed to return exit code 9 and did not break the pipeline, even when workflow violations were detected and the "Fail Pipeline on Violation" setting was enabled. The CLI now correctly enforces workflow policies by returning the appropriate exit code to ensure pipeline failures occur as expected when security violations are identified.

  • Fixed an issue in the Mend CLI where users with non-English characters in their profile names were denied access due to incorrect JWT decoding. The authentication process now correctly handles special characters to ensure seamless access for all users.

Mend Container: Version 26.9.1 (27-September-2026)

2026-09-27T00:00:00+00:00

Resolved Issues

  • Fixed an issue where certain vulnerabilities in RHEL8/Rocky8-based images were not correctly identified during filesystem scans. The scanner now properly surfaces OS-level CVEs even when no official fix is available from the distribution. Additionally, the matching logic has been enhanced to identify vulnerabilities in third-party and custom-rebuilt RPM packages by falling back to upstream ecosystem advisories when distribution-specific data is unavailable.

  • Fixed an issue where the Mend CLI local JSON export displayed a severity label that contradicted the CVSS score band within the same finding record. The export now ensures that the severity label and CVSS score are derived from the same source, providing consistent and accurate vulnerability data.

  • Fixed an issue where Container Image SBOM reports requested via the Reports API remained in a pending state for several hours. This delay was caused by an incorrect routing logic that skipped processing for cloud-native solution reports. The dispatch mechanism has been corrected to ensure that API-triggered report requests are promptly picked up and processed by the appropriate service, aligning the performance with UI-triggered requests.

  • Fixed an issue where the Containers Findings tab incorrectly displayed a "No Findings were found" message despite the Project and Scan Summary pages reporting existing container findings. This fix ensures that the findings list accurately reflects the summary counts.

  • Fixed an issue where specific vulnerabilities in Chainguard and Wolfi images were not correctly identified. This fix ensures accurate detection of Python packages on Wolfi base layouts and improves the matching logic for OpenSSL subpackages in Chainguard advisories.

  • Fixed an issue where container scans failed to report CVE-2026-18963 for keycloak-services versions in the 26.4.x and 26.6.x branches. The vulnerability data synchronization for container scanning was updated to correctly ingest and match Maven package ranges across all affected backport branches, ensuring critical vulnerabilities are accurately identified in container images.

  • Fixed an issue where the Containers view displayed outdated scan data because the latest scan pointer failed to advance upon scan completion. The logic has been corrected to ensure the Containers view consistently reflects the most recently finished scan.

  • Fixed an issue where `mend image --tar` failed to scan container image tarballs exported in pure OCI format. The scanner previously required a Docker-specific `manifest.json` file, which is not present in spec-compliant OCI image layouts. The CLI now correctly handles OCI-layout archives, including `index.json` and OCI-compliant blob structures, ensuring successful SBOM generation and vulnerability scanning for OCI-format exports.

  • Fixed an issue where updating a registry integration could overwrite stored service-user credentials with invalid data, causing subsequent scheduled scans to fail. The fix ensures that service-user state is managed server-side and includes a recovery mechanism to automatically refresh credentials if authentication failures occur during a scan.

Mend Unified Agent: Version 26.9.1 (28-September-2026)

2026-09-28T00:00:00+00:00

Resolved Issues

  • Fixed an issue where Python scans incorrectly reported zero dependencies when `python.localPackagePathsToInstall` was configured alongside a hierarchy tree. This occurred due to a parsing error in the dependency tree resolution that caused the entire manifest to be discarded if specific local packages or tooling artifacts could not be matched. The resolution logic has been corrected to ensure all identified dependencies are accurately reported.

  • Fixed an issue where using the -f or -file flag in `maven.additionalArguments` caused standard `pom.xml` files to be ignored and prevented the detection of nested manifests. The Maven resolver now correctly identifies both custom-named manifests and standard project files, supports all valid Maven flag formats, and ensures that quiet mode flags do not interfere with dependency resolution results.

  • Fixed an issue where transient network faults originating from packages other than `java.net`, such as `org.apache.http`, were incorrectly classified as permanent failures. This caused the Unified Agent to ignore the configured connection retry policy and abort the scan on the first attempt. The classification logic has been updated to ensure all recoverable I/O faults are properly retried, improving scan stability during intermittent network instability.

Mend for GitHub.com: Version 26.9.1 (27-September-2026)

2026-09-27T00:00:00+00:00

New Features and Updates

  • (SCA) (Open Beta) Mend for GitHub.com now supports the Bun package manager for JavaScript projects. This update allows for the automatic detection and reporting of both direct and transitive dependencies in projects using `package.json` alongside `bun.lock` or `bun.lockb` files, ensuring secure and reliable dependency management for the Bun ecosystem.

  • (SCA) Python constraints.txt files are now supported. This update allows the scanner to identify and apply dependency constraints, including those for transitive dependencies, without requiring manual references in requirements.txt. By honoring these constraints during resolution, the system reduces false-positive vulnerability reports and ensures scan results accurately reflect the specific package versions permitted in your environment.

  • (SAST) Increased the maximum comment length for the `/mend code suppress` and `/mend code comment` commands in GitHub to 65,536 characters. This update ensures that full technical justifications and detailed audit records are preserved without truncation, matching the character limits of the Mend Platform and GitHub.

  • (SAST) The integration now supports selecting which languages to scan, using the new algoLangs field in .mendsastcli-config.json. Until now, narrowing what a scan covered meant listing numeric engine IDs in the engines field. You can now specify languages by name instead, which is quicker to write and far easier to understand when someone reviews the configuration later.

Resolved Issues

  • (SCA) Fixed an issue where GitHub check-run updates were rejected with a "summary exceeds a maximum bytesize of 65535" error. The truncation logic was updated to ensure accuracy for multi-byte characters. Additionally, a maximum count was implemented for the resolved vulnerabilities section to prevent it from exceeding size constraints. These changes ensure that scan results are correctly surfaced on pull requests even with large result sets.

  • (SAST) Fixed an issue where manual SAST scans on non-default branches incorrectly tagged the project with the repository's default branch name. This fix ensures that the project tag accurately reflects the specific branch being scanned, maintaining consistency between the project metadata and the scanned commit.
