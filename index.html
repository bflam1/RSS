Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.9.3 (18-October-2026)

2026-10-18T00:00:00+00:00

New Features and Updates

  • Custom Roles, previously in closed beta, are now generally available. In this release, the role breakdown and the Create Role wizard are enhanced to provide a more intuitive custom role management experience.

  • (SCA) Introduced an option to generate a single aggregated SBOM file for application and multi-project scopes. This feature consolidates multiple project-level files into one document, deduplicating components and merging occurrence data across the selected scope. The aggregated export supports CycloneDX and SPDX standards, ensuring compliance and simplifying ingestion into downstream tooling. When multi-project scope is selected, projects must belong to the same application to maintain data integrity. Per-project generation remains the default structure for all report exports.

Resolved Issues

  • Fixed an issue where the last scan date returned by the Project Summaries API did not match the date displayed in the Mend UI. This discrepancy was caused by the API incorrectly recording the batch run time instead of the actual scan completion time. The system now ensures the API consistently reports the correct scan end time, maintaining data alignment across all interfaces.

  • Fixed an issue where the Mend Jira Data Center plugin created duplicate Jira tickets for the same security finding. By transitioning the deduplication and persistence logic to use a stable unique identifier instead of a transient one, the plugin now ensures only one ticket is generated per finding. This update prevents excessive ticket creation and stabilizes database growth, improving overall system performance and reliability.

  • (SCA) Fixed an issue where proprietary (in-house) components were incorrectly included in automation workflows for "Empty License" conditions, leading to false-positive violations. A new organizational setting, "Include Proprietary Libraries in Workflows," has been introduced to allow for the exclusion of these components by default. This ensures that only genuine third-party components with missing license data are flagged during scans.

  • (SCA) OS Inventory page fixes:

    • Fixed an issue where the OS Inventory page failed to load dependencies for certain projects, resulting in an error message and an HTTP 403 response. This was caused by a timeout during the source-file remapping process for projects with a high volume of files. The underlying logic has been optimized to handle large-scale dependency structures efficiently, ensuring the inventory grid loads correctly across all applications.

    • Fixed an issue where filtering the OS Inventory table by label caused the grid to display an error and fail to load data. This occurred due to an incorrect syntax format in the underlying API request. The filtering mechanism has been updated to ensure compatibility with the backend requirements, allowing users to successfully view and manage their inventory when label filters are applied.

  • (SCA) SBOM fixes:

    • Fixed an issue where SPDX SBOM imports containing circular dependencies or duplicate relationships caused the project hierarchy building process to hang, leading to scan timeouts. The import logic now correctly handles these complex dependency structures, ensuring scans complete efficiently and provide a full dependency tree.

    • Fixed an issue where CycloneDX SBOM imports failed when encountering valid SPDX license identifiers, such as FSL-1.1-MIT, in the license ID field. The import process now correctly validates these identifiers, preventing unhandled exceptions and ensuring successful SBOM processing.

    • Fixed an issue where CycloneDX SBOM imports failed due to an outdated SPDX license list. The validator now correctly handles newer SPDX license identifiers in both JSON and XML formats, preventing the rejection of valid SBOMs. Additionally, a bug was resolved that caused a generic error message instead of a specific validation failure notification.

Mend SAST: Version 26.9.2 (05-October-2026)

2026-10-05T00:00:00+00:00

New Features and Updates

  • Mend SAST now supports additional configuration files, such as YAML and JSON, to improve entry point detection. The engine automatically identifies API endpoints and maps them to their corresponding implementation classes. This enhancement ensures comprehensive security coverage for contract-first applications by automatically marking all generated entry point parameters as tainted, eliminating the need for manual configuration of custom frameworks.

  • Improved the accuracy of the Python engine across the following CWEs:

    • CWE-022 Path Traversal

    • CWE-078 OS Command Injection

    • CWE-079 XSS

    • CWE-089 SQL Injection

    • CWE-094 Code Injection

    • CWE-209 Error Message Info Exposure

    • CWE-295 Improper Cert Validation

    • CWE-532 Sensitive Info in Log

    • CWE-601 Open Redirect

    • CWE-918 SSRF

    • CWE-943 NoSQL Injection

Resolved Issues

  • Fixed an issue where the entry resolver failed when scanning certain AWS Lambda handler files in TypeScript.

Mend AI: Version 25.12.1 (05-January-2026)

2026-01-05T00:00:00+00:00

New Features and Updates

  • (Premium / Core) Introducing System Prompt Risk (open beta), a new detection and remediation offering by Mend AI, for mitigating risks posed by system prompts used in conversational AI interfaces.

    • A new System Prompt Risk table inventories system prompts and provides quick export/sharing and deep-link side panel for prompt context.

    • System Prompt Risks are integrated into the existing AI Security Risk Factors across Projects and Applications. The classification appears as a Conversational Interface chip, is filterable, and automatically participates in dashboards and workflows.

    • Remediation in the form of a hardened system prompt is available in the System Prompt side panel, providing clear, copy-ready remediation guidance for AppSec engineers and developers.

    • The AI Security Dashboard has been enriched with system prompt risk data.

    • System prompt risk data is also available via API.

Mend CLI: Version 26.9.2 (06-October-2026)

2026-10-06T00:00:00+00:00

Resolved Issues

  • Fixed an issue where top-level exclusions were not correctly matched in the CLI when the exclusion pattern started with a slash. This ensures that global file exclusions, such as default modules and symlinks, are properly recognized and respected during scans regardless of path formatting.

  • (SCA) Fixed an issue where Ruby scans run with the `--files-resolving` flag failed to report the installed Ruby version. The scanner now correctly identifies and records the Ruby version from the scanning environment while ensuring that unexpected version formats no longer cause the scan to crash.

  • (SCA) Conan projects now report the C/C++ compiler name and version alongside the Conan version during CLI scans. This enhancement provides better visibility into the toolchain used for C/C++ projects by extracting compiler details from the active Conan profile. The detection process is designed to be non-intrusive, ensuring that scans continue successfully even if the compiler information cannot be determined.

  • (SCA) Rust scans now report the installed Rust version even when Cargo is not present. Additionally, version lookups are now silent, removing unnecessary warnings from the logs when a version cannot be determined. This ensures more accurate toolchain reporting without impacting scan performance or log clarity.

  • (SCA) Fixed an issue where CLI scans of Gradle projects reported the Gradle version with unnecessary text and JVM information. The CLI now reports only the bare Gradle version, ensuring consistent data formatting and accurate grouping within the SCA Toolchain Versions dashboard.

  • (Container) Fixed an issue where the severity distribution in the `mend image` JSON report did not match the Platform UI for the same scan. This discrepancy, which caused some findings to be reported at a higher severity level in the JSON output, has been resolved to ensure consistency across all reporting interfaces.

Mend Unified Agent: Version 26.9.2 (06-October-2026)

2026-10-06T00:00:00+00:00

Resolved Issues

  • Fixed an issue where the Swift Package Manager (SPM) resolver incorrectly reported local package targets as top-level direct dependencies. The resolver now accurately resolves the dependency tree, ensuring local targets are correctly nested and transitive dependencies are properly identified without duplication.

  • Fixed an issue where Docker image scans incorrectly reported Python packages that had been removed or upgraded in later image layers. The Unified Agent now correctly identifies and ignores Docker whiteout markers, ensuring that only the package versions present in the final image are reported, which prevents inaccurate security and license alerts.

Mend for GitHub Enterprise: Version 26.9.1.4 (01-October-2026)

2026-10-01T00:00:00+00:00

Resolved Issues

  • Fixed an issue where long-running issue publishing processes failed due to GitHub installation access token expiration. The system now proactively refreshes tokens before they expire, ensuring uninterrupted synchronization for large repositories.

  • Introduced a new configuration parameter, `issue.update.pause`, to independently control the delay after issue updates and closures, to solve an issue of tied throttling pauses. This allows for more granular performance tuning by separating update pauses from creation pauses, optimizing SCM API interactions and reducing the risk of rate limiting without affecting existing creation workflows.

  • Fixed an issue where the controller incorrectly ignored errors returned with an HTTP 200 status. The controller now correctly identifies and logs these error responses, improving diagnostic capabilities for startup failures.

  • Fixed an issue where attempting to rebuild the integration's scanner image would fail due to a missing Scala package. The issue only affected setups with Scala enabled.
