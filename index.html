Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.8.1 (23-August-2026)

2026-08-23T00:00:00+00:00

New Features and Updates

  • Introduced Account-Level (Global) Workflows, enabling administrators to define and manage workflows centrally across multiple organizations. This feature eliminates manual duplication and ensures consistent governance by allowing workflows to be configured at the account level and propagated to selected organizations. Account-level workflows are clearly identified within organization views, and administrators can control whether organization-level admins have the authority to enable or disable them locally. This update also includes comprehensive API support for managing global workflows.

  • The Administration page sidebar has been updated to include a categorized, collapsible navigation structure, improving discoverability and aligning with the Application and Project pages. As part of this update, AI Usage settings have been moved from the General tab to a dedicated AI Usage tab within the new AI category. Additionally, the Engine Settings section now features specific sub-headers for AI, Code, and Dependencies for a more organized administrative experience.

Resolved Issues

  • (SCA) Fixed an issue where, under certain conditions, generating the Dependencies Findings Report in Excel format at the application scope failed to produce a report, incorrectly stating that no projects matched the requested scope. The report now correctly includes all relevant project data when generated at the application level.

Mend SAST: Version 26.8.1 (24-August-2026)

2026-08-24T00:00:00+00:00

New Features and Updates

  • When viewing finding details in the Mend Platform, you can now see the probability risk factor next to each data flow, providing more granular information.

  • Mend SAST now includes detection for CWE-99: Improper Control of Resource Identifiers / Client Resource Injection in JavaScript/TypeScript. This update expands security coverage by identifying vulnerabilities where untrusted input can influence the selection of resources, such as files or network connections, helping to prevent client-side resource injection attacks.

  • Mend SAST now supports CWE-319: Cleartext Transmission of Sensitive Information and CWE-321: Use of Hard-coded Cryptographic Key for Rust.

Resolved Issues

  • Fixed an issue where Java SAST scans performed on a non-system drive, such as a D: drive, failed to report findings. The engine now correctly handles cross-drive paths, ensuring consistent detection results regardless of the scan's location.

  • Fixed an issue where the iOS Objective-C engine incorrectly flagged standard Apple APIs—including `removeItemAtPath` and `NSUserDefaults`—as security vulnerabilities based on their presence alone. The engine now requires evidence of external control or sensitive data usage before reporting File Manipulation (CWE-73) or Insecure Data Storage findings. These improvements significantly reduce false positives in mobile application scans by ensuring that standard in-memory and lifecycle operations are not misidentified as risks.

  • Fixed an issue where VB.net scans would experience severe performance degradation or fail to complete when processing large files during the deep analysis phase. The engine has been optimized to significantly improve scan speeds, ensuring that complex files complete analysis instead of being skipped or timing out.

  • Fixed an issue where the Mend Agentic MCP Integration's SAST tool failed to provide remediation suggestions due to an internal server error. The LLM remediation service has been stabilized to ensure consistent performance and successful tool calls within the integration.

  • Fixed an issue where Mend CLI SAST scans failed to upload results after long-running engine analysis. This occurred when network firewalls closed idle TCP connections during extended analysis phases, leading to EOF errors. The system now gracefully handles these network conditions to ensure scan results are successfully submitted even after periods of inactivity.

Mend AI: Version 25.12.1 (05-January-2026)

2026-01-05T00:00:00+00:00

New Features and Updates

  • (Premium / Core) Introducing System Prompt Risk (open beta), a new detection and remediation offering by Mend AI, for mitigating risks posed by system prompts used in conversational AI interfaces.

    • A new System Prompt Risk table inventories system prompts and provides quick export/sharing and deep-link side panel for prompt context.

    • System Prompt Risks are integrated into the existing AI Security Risk Factors across Projects and Applications. The classification appears as a Conversational Interface chip, is filterable, and automatically participates in dashboards and workflows.

    • Remediation in the form of a hardened system prompt is available in the System Prompt side panel, providing clear, copy-ready remediation guidance for AppSec engineers and developers.

    • The AI Security Dashboard has been enriched with system prompt risk data.

    • System prompt risk data is also available via API.

Mend Unified Agent: Version 26.8.1 (24-August-2026)

2026-08-24T00:00:00+00:00

Resolved Issues

  • Fixed an issue where the Unified Agent logged a misleading warning and incorrectly inflated the "total libraries affected by policy" count in scan reports. This occurred because libraries with no matching policies were incorrectly treated as having an unsupported action type. The reporting logic has been updated to correctly identify and exclude these libraries from policy-affected statistics, ensuring more accurate scan report data and cleaner logs.

Mend Developer Platform: Version 26.8.1 (23-August-2026)

2026-08-23T00:00:00+00:00

New Features and Updates

  • The "Last Updated At" timestamp has been removed from the individual job detail page to streamline the interface and reduce visual noise. This information remains available on the jobs table and list pages, where it continues to provide valuable context for comparing multiple jobs at a glance. This update ensures that the most relevant job details, such as completion time and duration, are prioritized for a cleaner user experience.

  • (GitLab.com) A new visual indicator in the group tree was introduced to show when a first sync is in progress. Newly onboarded groups now appear with a "Setting up..." badge, ensuring clear visibility into the setup status. The group node remains in a pending state until the initial sync completes, at which point it automatically transitions to an active, interactive state.

Mend for GitHub.com: Version 26.8.1 (23-August-2026)

2026-08-23T00:00:00+00:00

New Features and Updates

  • In GitHub issues only a single dependency file path is displayed when a vulnerability affects multiple manifests. To clarify that the displayed path is one of potentially several affected locations, the label has been updated to "Sample Path to Dependency File".

  • (SAST) Mend for GitHub.com can now automatically send SAST findings to GitHub Advanced Security using the exportToGHAS scan parameter.

    • This feature requires repository Read and write access to Code scanning alerts.

  • (SAST) Remediations are now triggered by commenting /mend remediate, instead of by a checkbox. Mend replies with a confirmation comment once the command is processed, including a clear message if something goes wrong. Existing pull requests and issues continue to work as before.

  • (SAST) Added the option to receive a single comment summarizing all findings, instead of a separate comment for each one. Furthermore, it is now possible to set a severity threshold so that only findings at or above the severity level you care about are reported. The severity threshold also applies if you keep the classic per-finding comments, giving you a simple way to reduce the number of PR comments either way.

Mend for GitHub Enterprise: Version 26.8.1.1 (23-August-2026)

2026-08-23T00:00:00+00:00

Unified Agent 26.7.2.1 | Renovate 44.3.2 | Remediate 26.7.2 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • Upgraded the core technology stack in the controller to Spring Boot 4.1.0, including Spring Framework 7, Hibernate 7, and Spring Data JPA 4.x. This update ensures continued security support and leverages the latest performance improvements and features within the Spring ecosystem, providing a more robust and modern foundation for repository integrations.

  • Enhanced diagnostic logging for the webhook consumer to provide better visibility into queue-claim attempts and idle periods. This update allows for more effective troubleshooting of webhook processing delays by capturing detailed logs of claim outcomes and sleep durations when the queue is empty. These logs are disabled by default and can be activated via environment variables for targeted investigations, ensuring no impact on standard system performance while improving overall observability.

  • In GitHub issues only a single dependency file path is displayed when a vulnerability affects multiple manifests. To clarify that the displayed path is one of potentially several affected locations, the label has been updated to "Sample Path to Dependency File".

  • The enableSCA parameter is now fully supported. This update aligns the self-hosted experience with GitHub.com , allowing users to reliably enable or disable SCA scans at the repository level across all entry points.

  • (SAST) Remediations are now triggered by commenting /mend remediate, instead of by a checkbox. Mend replies with a confirmation comment once the command is processed, including a clear message if something goes wrong. Existing pull requests and issues continue to work as before.

  • (SAST) Added the option to receive a single comment summarizing all findings, instead of a separate comment for each one. Furthermore, it is now possible to set a severity threshold so that only findings at or above the severity level you care about are reported. The severity threshold also applies if you keep the classic per-finding comments, giving you a simple way to reduce the number of PR comments either way.

Resolved Issues

  • Updated the reachability scan flow to ensure the `isBaseBranch` parameter is correctly passed during scan requests. This alignment across all scan paths ensures consistent scan parameter handling for repository integrations, improving the accuracy of branch-specific scan data.

  • Fixed an issue where pip dependencies in certain setups were incorrectly reported as unresolved, causing successful scans to be marked as partial.

  • Fixed an issue where global scan settings were ignored in favor of default values, in certain setups. The inheritance logic now correctly processes multi-level configurations to ensure all parent settings are applied as expected.
