Mend.io Unified Release Notes

Mend AppSec Platform: Version 26.8.2 (06-September-2026)

2026-09-06T00:00:00+00:00

New Features and Updates

  • Introduced a new suppression tool in Agentic Integrations, enabling developers to effectively manage security findings directly within their IDE or AI agent workflow. This update supports both single and bulk suppression or unsuppression actions across all scanning engines, including SAST and SCA. By integrating triage capabilities into the development environment and ensuring UI updates reflect within seconds, the enhancement reduces context-switching and streamlines the remediation process.

  • (SCA) Introduced a unified vulnerability remediation experience across the Mend Platform by standardizing fix logic and recommendations, adding a Top Fix column in the Findings table, updating the Remediation tab, and ensuring consistent metadata for reliable and clear vulnerability fixes.

    • This update may result in fewer remediation suggestions per vulnerability and overall reduced noise-level, due to the increased accuracy of the fix logic.

    • This feature will be rolled out gradually in the next couple of weeks.

Resolved Issues

  • Fixed an issue where SBOM report generation jobs could remain in a pending state indefinitely during periods of high volume.

  • Fixed an issue where filtering the Application Violations table by project failed and displayed an error row.

  • Fixed an issue where license status toggles in the library drawer were incorrectly enabled for users without update permissions. The interface now correctly disables these controls and provides a descriptive tooltip when a user lacks the required access, ensuring the user experience aligns with backend authorization levels and preventing non-persistent UI changes.

  • (IaC) Fixed an issue where the Project Summary page incorrectly displayed "IaC Scan Not Executed" even when Infrastructure as Code (IaC) findings were present. The statistics synchronization has been corrected to ensure the summary widget accurately reflects scan results and finding counts.

Mend SCA: Version 26.8.2 (06-September-2026)

2026-09-06T00:00:00+00:00

New Features and Updates

  • Introduced a unified vulnerability remediation experience across the Mend Platform by standardizing fix logic and recommendations, adding a Top Fix column in the Findings table, updating the Remediation tab, and ensuring consistent metadata for reliable and clear vulnerability fixes.

    • This update may result in fewer remediation suggestions per vulnerability and overall reduced noise-level, due to the increased accuracy of the fix logic.

    • This feature will be rolled out gradually in the next couple of weeks.

  • Introduced support for the European Union Vulnerability Database (EUVD) as a primary security data source. This integration provides enriched vulnerability data, including dedicated CVSS scores and exploitability information sourced directly from ENISA. By incorporating this comprehensive European feed alongside existing sources, the platform delivers broader visibility into global vulnerability trends and ensures more robust protection through enhanced security data coverage.

Resolved Issues

  • Fixed an issue where the Libraries grid experienced significant loading delays for organizations with large inventories. The underlying query logic has been optimized to ensure faster page responses and improved performance when viewing dependency details.

  • Fixed an issue where the Alerts view and Library view displayed inconsistent vulnerability data for specific Java libraries. This synchronization fix ensures that security alerts accurately reflect the library's status across all platform views, providing a reliable and unified source of truth for vulnerability management.

  • Fixed an issue where the jsPDF `polyfills.umd.js` file (v4.2.0) was incorrectly identified as version 3.0.2. The mapping has been corrected to ensure accurate identification and security reporting for jsPDF v4.2.0.

  • Fixed an issue where larastan packages were incorrectly flagged with CVE-2021-41248.

  • Fixed an issue where newly published CVEs were not automatically appearing on the Alerts > Vulnerability page within the expected synchronization cycle.

Mend SAST: Version 26.8.2 (07-September-2026)

2026-09-07T00:00:00+00:00

New Features and Updates

  • Improved detection accuracy of JavaScript /TypeScript analysis engine across 11 CWEs. Key refinements include tuning detection for React controlled components to prevent false positives where query parameters flowing into escaped JSX attributes were incorrectly flagged as DOM-based XSS. In detail, the following CWEs were updated:

    • CWE-22 — Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')

    • CWE-78 — Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')

    • CWE-79 — Improper Neutralization of Input During Web Page Generation ('Cross-site Scripting')

    • CWE-89 — Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')

    • CWE-90 — Improper Neutralization of Special Elements used in an LDAP Query ('LDAP Injection')

    • CWE-94 — Improper Control of Generation of Code ('Code Injection')

    • CWE-117 — Improper Output Neutralization for Logs

    • CWE-295 — Improper Certificate Validation

    • CWE-601 — URL Redirection to Untrusted Site ('Open Redirect')

    • CWE-918 — Server-Side Request Forgery (SSRF)

    • CWE-943 — Improper Neutralization of Special Elements in Data Query Logic (NoSQL / query-language injection)

Resolved Issues

  • Fixed an issue where false-positive XSS and SQL injection findings were reported in ColdFusion projects. Mend SAST now accurately handles local variables assigned to hardcoded integer literals and correctly identifies parameterized queries using `` or numeric validation guards. Additionally, scan performance and reliability were significantly improved.

  • Fixed an issue that caused the IDE plugins to crash in certain scenarios when fetching the existing results.

  • Fixed an issue in the IDE plugins causing some of the Bitbucket Data Center repositories to be matched incorrectly with the Mend Platform projects.

Mend Container: Version 26.8.2 (06-September-2026)

2026-09-06T00:00:00+00:00

Resolved Issues

  • Fixed an issue where the Container Attribution Report export endpoint returned an empty report regardless of the number of scanned container images. The export now correctly includes attribution data for the organization's container scans.

  • Fixed an issue where container scans incorrectly matched CVEs to package versions outside their affected range and reported inconsistent vulnerability counts for unchanged images. The fix ensures that vulnerability matching strictly adheres to documented version ranges and provides stable, reliable results across consecutive scans.

  • Fixed an issue where Docker Hardened Image (DHI) VEX statements were not correctly attached to Go-language application package findings. While VEX data was successfully applied to OS-level packages, it was missing for language-specific dependencies. This fix ensures that version-matched VEX statements are accurately reflected as risk factors for Go packages, providing a more precise security posture for container scans.

Mend AI: Version 25.12.1 (05-January-2026)

2026-01-05T00:00:00+00:00

New Features and Updates

  • (Premium / Core) Introducing System Prompt Risk (open beta), a new detection and remediation offering by Mend AI, for mitigating risks posed by system prompts used in conversational AI interfaces.

    • A new System Prompt Risk table inventories system prompts and provides quick export/sharing and deep-link side panel for prompt context.

    • System Prompt Risks are integrated into the existing AI Security Risk Factors across Projects and Applications. The classification appears as a Conversational Interface chip, is filterable, and automatically participates in dashboards and workflows.

    • Remediation in the form of a hardened system prompt is available in the System Prompt side panel, providing clear, copy-ready remediation guidance for AppSec engineers and developers.

    • The AI Security Dashboard has been enriched with system prompt risk data.

    • System prompt risk data is also available via API.

Mend Unified Agent: Version 26.8.2 (07-September-2026)

2026-09-07T00:00:00+00:00

Resolved Issues

  • Fixed an issue where pip requirements.txt scans on Windows could report zero dependencies when using an absolute path for the pip executable (python.pipPath). This occurred because the scan bypassed the activated virtual environment, causing dependency mismatches that invalidated the entire manifest. The resolution process now correctly honors the virtual environment activation, ensuring accurate dependency inventory and reporting.

  • Fixed an issue where the Ant dependency resolver in the Unified Agent used inconsistent log prefixes, such as "Ant-Resolver" and "Ant Resolver," across different debug statements. The log prefix has been standardized to a single consistent format to improve log readability and simplify troubleshooting.

  • Fixed an issue where NuGet transitive dependencies were incorrectly reported with the version identity declared in a package's nuspec file rather than the version actually restored on disk. This occurred when the restored version was missing from the global NuGet cache, causing the scanner to default to the nuspec-declared version. The resolver now correctly prioritizes the project's local restore directory to ensure accurate version identification and inventory reporting.

Mend Developer Platform: Version 26.8.2 (06-September-2026)

2026-09-06T00:00:00+00:00

New Features and Updates

  • (GitLab.com) Introduced a hierarchical tree view for the Installed Groups list, replacing the previous flat list to clearly display group relationships. This update includes bulk selection and deletion capabilities, allowing users to manage multiple groups simultaneously while providing a detailed confirmation dialog that specifies which groups and repositories will be removed or retained.

  • (Bitbucket) Following the deprecation of Bitbucket Cloud's native issue tracker, the Developer Platform was updated to ensure a seamless user experience and prevent integration errors. The "Issues" toggle is now disabled for Bitbucket Cloud across all scan engines, including Dependencies, Code Security, and Infrastructure as Code. An explanatory tooltip has been added to the interface, and backend processes have been updated to stop calling the deprecated Bitbucket endpoints. These changes prevent failing API calls and ensure that scan engine settings remain accurate and functional.

  • (SCA) Python constraints.txt files are now supported. This update allows the scanner to identify and apply dependency constraints, including those for transitive dependencies, without requiring manual references in requirements.txt. By honoring these constraints during resolution, the system reduces false-positive vulnerability reports and ensures scan results accurately reflect the specific package versions permitted in your environment.

Resolved Issues

  • (SCA) (Bitbucket) Fixed an issue where SCA scans could remain stuck in a "RUNNING" state indefinitely. The fix ensures that all scan processes are correctly finalized or closed, providing accurate status updates and visibility within the user interface.

Mend for GitHub Enterprise: Version 26.8.1.1 (23-August-2026)

2026-08-23T00:00:00+00:00

Unified Agent 26.7.2.1 | Renovate 44.3.2 | Remediate 26.7.2 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • Upgraded the core technology stack in the controller to Spring Boot 4.1.0, including Spring Framework 7, Hibernate 7, and Spring Data JPA 4.x. This update ensures continued security support and leverages the latest performance improvements and features within the Spring ecosystem, providing a more robust and modern foundation for repository integrations.

  • Enhanced diagnostic logging for the webhook consumer to provide better visibility into queue-claim attempts and idle periods. This update allows for more effective troubleshooting of webhook processing delays by capturing detailed logs of claim outcomes and sleep durations when the queue is empty. These logs are disabled by default and can be activated via environment variables for targeted investigations, ensuring no impact on standard system performance while improving overall observability.

  • In GitHub issues only a single dependency file path is displayed when a vulnerability affects multiple manifests. To clarify that the displayed path is one of potentially several affected locations, the label has been updated to "Sample Path to Dependency File".

  • The enableSCA parameter is now fully supported. This update aligns the self-hosted experience with GitHub.com , allowing users to reliably enable or disable SCA scans at the repository level across all entry points.

  • (SAST) Remediations are now triggered by commenting /mend remediate, instead of by a checkbox. Mend replies with a confirmation comment once the command is processed, including a clear message if something goes wrong. Existing pull requests and issues continue to work as before.

  • (SAST) Added the option to receive a single comment summarizing all findings, instead of a separate comment for each one. Furthermore, it is now possible to set a severity threshold so that only findings at or above the severity level you care about are reported. The severity threshold also applies if you keep the classic per-finding comments, giving you a simple way to reduce the number of PR comments either way.

Resolved Issues

  • Updated the reachability scan flow to ensure the `isBaseBranch` parameter is correctly passed during scan requests. This alignment across all scan paths ensures consistent scan parameter handling for repository integrations, improving the accuracy of branch-specific scan data.

  • Fixed an issue where pip dependencies in certain setups were incorrectly reported as unresolved, causing successful scans to be marked as partial.

  • Fixed an issue where global scan settings were ignored in favor of default values, in certain setups. The inheritance logic now correctly processes multi-level configurations to ensure all parent settings are applied as expected.
