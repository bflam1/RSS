Mend AppSec Platform: Version 26.10.2 (15-November-2026)

2026-11-15T00:00:00+00:00

New Features and Updates

  • The Mend MCP Server is now available as a Claude Connector, enabling one-click installation and discovery within the Claude environment. This integration provides comprehensive access to both developer and platform tools, allowing for seamless repository scanning, remediation, and organization-wide security posture reporting. Authentication follows standard protocols, ensuring secure, permission-gated access to Mend findings and fixes directly within the Claude assistant, without manual configuration or infrastructure maintenance. For more configuration details, visit our documentation.

  • (SAST) Introduced a new guided onboarding wizard that enables users to easily activate SAST scanning for their repositories directly from the Mend Platform. This streamlined flow enables quick repository selection and pilot scan execution without manual configuration, providing immediate visibility into scan results and security findings. Additionally, users can now delegate the onboarding process to colleagues via email invitations, facilitating team-wide adoption.

  • The Forge tab has been retired to simplify your platform experience. To explore upcoming capabilities and collaborate directly on our roadmap, we invite you to join our Charter Partner Program and attend our customer webinars. Reach out to your Customer Success Manager to learn more.

  • (UI updates) The Mend Platform has a refreshed look aligned with Mend's updated brand identity. This includes a new color palette across the interface, a redesigned login experience, a new Mend-branded loading animation, and a unified, more compact button design for greater consistency. These are visual changes only and do not affect existing workflows or functionality.

Resolved Issues

  • (SCA) Fixed an issue where the Projects page Languages filter excluded certain projects due to case-sensitive matching of language labels. The filter now correctly identifies and includes all relevant projects regardless of whether the language label is cased as "Go", "GO", or includes a suffix like "Go*".

Mend SAST: Version 26.10.2 (16-November-2026)

2026-11-16T00:00:00+00:00

New Features and Updates

  • Introduced a new guided onboarding wizard that enables users to easily activate SAST scanning for their repositories directly from the Mend Platform. This streamlined flow enables quick repository selection and pilot scan execution without manual configuration, providing immediate visibility into scan results and security findings. Additionally, users can now delegate the onboarding process to colleagues via email invitations, facilitating team-wide adoption.

  • Enhanced the Global Scan Configuration by implementing language filtering based on engine generation. This update ensures that only languages supported by the current engine generation are displayed, streamlining the configuration process and improving selection accuracy for scan setups.

Resolved Issues

  • Fixed an issue where it failed to detect vulnerabilities in Express route handlers wrapped in `asyncHandler` or similar wrapper functions. The JavaScript engine now correctly identifies these wrapped functions as entry points, ensuring comprehensive analysis and reporting of security findings, such as SSRF (CWE-918) and Log Forging (CWE-117), within these handlers.

  • Enhanced the JavaScript Gen 2 engine to improve detection of DOM XSS vulnerabilities. The analysis now identifies tainted data in additional jQuery AJAX callback shapes.

  • Improved the accuracy of the Swift Gen 2 engine by reducing false positives for CWE-117 (Log Injection) and CWE-295 (Insecure TLS Configuration). Swift `print` and `debugPrint` findings are now categorized as low-probability, hiding them by default to focus on persistent logging sinks. Additionally, the engine now correctly recognizes certificate and public-key pinning in `URLSession` challenge handlers, preventing incorrect reports of insecure configurations when proper validation is present.

Mend CLI: Version 26.10.2.4 (16-November-2026)

2026-11-16T00:00:00+00:00

New Features and Updates

  • (SCA) Java reachability analysis now includes the ability to automatically fetch missing dependency JAR files from configured Maven repositories when they are not available locally. This ensures comprehensive reachability results and prevents scan interruptions for Java projects, providing parity with existing functionality for other languages.

  • (SCA) Enhanced Reachability logging to include the maximum JVM heap size and ensure memory usage is recorded even when a language analysis fails. This improvement provides better visibility into resource consumption during failed scans, facilitating more accurate troubleshooting and environment sizing.

Resolved Issues

  • (SCA) Fixed an issue where Python reachability analysis incorrectly reported single-file modules as unreachable when a CVE lacked specific vulnerable elements. The dependency graph labeling now correctly matches the entry graph, ensuring accurate reachability results for these modules. Additionally, the analysis process no longer writes temporary files into the installation directory and ignores stale synthetic folders, improving scan reliability and environment integrity.

  • (SCA) Fixed an issue where editable pip installs of a project's own package were incorrectly reported as third-party libraries. This caused Python reachability scans to fail with an invalid dependency error when the package could not be retrieved from external indexes. The resolver now correctly identifies these as internal modules, ensuring successful reachability analysis for Python projects using editable installs.

  • (SCA) Fixed an issue where the Unified Agent failed to parse dependency graph output from Pipenv versions 2026.7.0 and later. This failure caused the resolver to fall back to an alternative method that incorrectly reported packages not present in the project's lock file as direct dependencies, leading to inaccurate vulnerability alerts. The parser now correctly handles the additional fields introduced in newer Pipenv versions, ensuring accurate dependency resolution and reporting.

  • (SCA) Introduced a new configuration setting, reachabilityMaxRamPercentage, to provide granular control over memory allocation for the Reachability engine. This setting allows users to specify the maximum RAM percentage for the Reachability JVM, preventing memory-related failures in constrained environments. Additionally, out-of-memory errors are now surfaced as clear warning logs and SCA results, ensuring better visibility into analysis gaps without requiring manual log inspection.

  • (SCA) Fixed an issue where the Python pip no-exec resolver failed to correctly handle certain package index responses. The local index now properly interprets upstream 403 errors as missing packages rather than errors, correctly applies the `uploaded-prior-to` setting for date-gated environments, and supports large index pages through gzip compression. These improvements ensure accurate dependency resolution and prevent scans from incorrectly reporting success when dependencies are missing.

Mend for GitHub Enterprise: Version 26.10.1.2 (13-November-2026)

2026-11-13T00:00:00+00:00

Unified Agent 26.9.3.1 | Renovate 44.188.2 | Remediate 26.10.2 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • (SCA) Introduced a new configuration setting, reachabilityMaxRamPercentage, to provide granular control over memory allocation for the Reachability engine. This setting allows users to specify the maximum RAM percentage for the Reachability JVM, preventing memory-related failures in constrained environments. Additionally, out-of-memory errors are now surfaced as clear warning logs and SCA results, ensuring better visibility into analysis gaps without requiring manual log inspection.

  • (SCA) Java reachability analysis now includes the ability to automatically fetch missing dependency JAR files from configured Maven repositories when they are not available locally. This ensures comprehensive reachability results and prevents scan interruptions for Java projects, providing parity with existing functionality for other languages.

  • (SCA) Enhanced the tool-version check mechanism to support concurrent execution across multiple package managers, ensuring thread safety and accurate logging. Manual Go versioning now correctly applies to projects detected via legacy manifests, including `Godeps.json`, `.gopmfile`, `vendor.json`, and `vendor.conf`. Additionally, command output recording now captures both standard output and diagnostics streams, improving version detection for tools like Java and Scala and providing more detailed failure messages in scan results.

  • (SCA) A hook script that runs longer than 60 minutes (configurable, in minutes, with MEND_SCA_HOOKS_TIMEOUT) is stopped along with the processes it started, reported as a warning in the scan results, and the scan continues. A process a hook starts in the background must redirect its own output; the scan no longer waits for it.

Resolved Issues

  • (SCA) Fixed an issue where the SCA wrapper could inadvertently load and execute Composer plugins from a scanned project's directory during version checks. The system now explicitly disables plugin loading for these checks, ensuring that scanning untrusted repositories does not result in unauthorized code execution on the scan host.

  • (SCA) Fixed an issue where scan engine error messages could be truncated or missing from logs when an engine exited before finished reading the output. This ensures that complete error details are consistently captured and displayed in logs, even under high system load.

Mend for Bitbucket DC: Version 26.10.1.1 (01-November-2026)

2026-11-01T00:00:00+00:00

Unified Agent 26.9.2.1 | Renovate 44.176.3 | Remediate 26.9.3.3 | Pre-Scan Builder (PSB) 25.8.1

New Features and Updates

  • Updated Mend documentation to provide validated recommendations for scanner memory sizing while maintaining scan stability and performance when running Reachability scans.

Resolved Issues

  • Fixed an issue where reachability analysis would hang or time out on large multi-module Maven repositories. This occurred because excessively large debug log lines exceeded the scanner's processing limit, causing the scan to stall. The logging mechanism has been optimized to prevent these large outputs, ensuring stable and timely completion of reachability scans for complex projects.

  • Fixed an issue where JavaScript Reachability enrichment failed for projects with `devEngines` requirements that did not match the scanner's Node.js version. The enrichment process now uses the `--force` flag for metadata retrieval to ensure compatibility regardless of local engine constraints. Additionally, error reporting was improved to include specific npm error codes, and sensitive credential information was removed from command logs to enhance security.

  • Fixed an issue where scanSummaryInfo values, including per-step statistics and failure reasons, were missing from enriched update requests during Reachability scans. The enriched request now correctly retains all original metadata while including the vulnerability analysis results.
